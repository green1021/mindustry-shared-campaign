# v160.4 vanilla economy contract (recorded once for M4)

These are source contracts, **not claims that they work transparently across isolated JVMs**. No downloads were needed for M4; installed engine API/bytecode inspection was read-only. Links below pin the established source version.

- [Sector.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/type/Sector.java): `items()` uses the live core when `isBeingPlayed()`, otherwise `info.items`. `addItems()` requires `hasBase()` and follows the same live/inactive distinction. `hasBase()` uses save presence and `info.hasCore`, not merely an unlocked preset. M4's headless directory instead explicitly calls its entries **owned-saved** based on the isolated save's actual sector metadata and `nocores=false`; it does not fabricate desktop `Saves.SaveSlot` instances or claim the complete vanilla launch eligibility flow.
- [ResearchDialog.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/ui/dialogs/ResearchDialog.java): `rebuildItems()` aggregates sectors with `hasBase() && !isFrozen()` on planets matching the tech tree. Research removes proportionally from other sectors first and the current sector last. This does not imply a permanently pooled core inventory. A coherent remote-active snapshot and routed deductions remain future integration.
- [LaunchPad.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/world/blocks/campaign/LaunchPad.java): payload removal/export accounting is part of the flow; direct destination `addItems()` applies only in `legacyLaunchPads` mode.
- [LandingPad.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/world/blocks/campaign/LandingPad.java) and [SectorInfo.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/game/SectorInfo.java): new landing pads consume import rates/timers. Cross-process transfer cannot be implemented by assuming every launch directly credits another core.
- [Universe.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/game/Universe.java): `runTurn()` simulates inactive sectors. A worker cannot independently simulate sectors active in other workers. **Explicit M4 activation suspends all offline turns in this bounded experiment**, including on the host, until a coordinator-aware vanilla integration exists. It does not replace them with another economy. Lighting/time updates continue; replacing Universe is an experimental headless-only limitation, not a production desktop campaign implementation.
- [SaveIO.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/io/SaveIO.java), [SaveVersion.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/io/SaveVersion.java), and [Logic.java](https://github.com/Anuken/Mindustry/blob/v160.4/core/src/mindustry/core/Logic.java): actual `SaveIO.write(Fi, SaveOptions)` writes engine world bytes. `Logic`'s campaign `SaveLoadEvent` calls `SectorInfo.write()`, which restores core items from that sector's info. A fresh worker's empty settings otherwise erase the loaded count (observed M4 failure). M4 embeds **the saved sector's own prepared SectorInfo**, plus campaign identity, in SaveOptions extra tags in the same atomic `.msav`; it restores that metadata before `SaveIO.load`. No other world's inventory is used. `Logic.play()` is new-game initialization and can clear cores to starting loadout; a loaded save resumes with `state.set(State.playing)` instead.

## Required future integration

Preserve per-sector inventories, vanilla transfers, and vanilla research cost semantics. Route remote-active operations to the exclusive owner and produce coherent research snapshots. Add one coordinated inactive-sector simulation rather than N independent universes. None of these are delivered by M4, and M2/M3 test debits are not a proposed gameplay economy.
